# Groq/Llama 客服配置与费用

一期只使用 Groq/Llama，不启用豆包。模型默认 `llama-3.3-70b-versatile`；若供应商下架，选择其当前可用模型并重新验收。

## 开启流程

1. 在 Groq 账号创建项目专用API key，保存到 Pages Secret `GROQ_API_KEY`。
2. 确认 `CHAT_LOGS` 为私有R2绑定，D1已迁移。
3. 先保持 `AI_ENABLED=false` 完成其他配置，再设为 true 真实发送一条问题。
4. 在 Groq 控制台查看本次用量，在私有R2桶找到按日期目录保存的JSON。包含时间、语言、问题、回复和返回的 token 用量，不主动保存IP或邮箱。
5. 配置R2日志生命周期30天；`CHAT_RETENTION_DAYS` 是配置说明，不会自动创建供应商生命周期规则。

## 行为与安全

- 页面默认按浏览器 Accept-Language 进入中/英/西，访客可手动切换，AI按当前页面语言回复。
- 访客必须明确勾选AI数据处理同意，才允许发送。输入最高2000字符，只带最近6条上下文。
- 默认输出400 token，代码最高600。每IP每小时12次，全站每日100次、每月1000次；D1原子计数阻止并发越限。
- 按UTC统计日期。失败请求保守计入额度，不退回。达到额度则拒绝，不自动换模型或付费提供商。
- 关键词意向识别引导联系表单。AI不主动收集敏感信息，不承诺结果。
- 提示词在 `shared/content.js` 的 `systemPrompt`。用户的“已定稿提示词”未提供，当前是供审核的初稿。
- API错误或密钥缺失时显示联系表单入口，不把异常、凭据或供应商响应原文返回访客。
- 对话日志保存失败则不返回成功回复；此前可能已经产生供应商费用。

## 成本边界

调用次数和 token 上限不是精确美元预算。总成本还包括输入上下文、供应商计费规则、网络重试、Worker/D1/R2使用量；生产应设置保守额度、供应商可用的消费硬限额/预付额度和账单告警。若 Groq 当前账户不支持消费硬上限，不要把邮件告警说成硬停机。可以随时将 AI_ENABLED=false 作为网站开关。

定期在管理员“重试待同步”操作中清理过期限流记录；高流量时可另设Cloudflare定时清理任务。首期不含 RAG、自动外呼或复杂线索分配。
